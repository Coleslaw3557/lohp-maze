# LS625X RS232 protocol cut sheet

Everything the Cuddle projector (ViewSonic LS625X) exposes on its DE-9,
distilled from the official user guide's "RS232 command table" (printed
pp. 63–71; guide PDF mirrored at `~/lohp/LS625X_User_Guide.pdf`, source
https://cdn-docs.av-iq.com/other/LS625X_User%20Guide.pdf) plus live probes
on our unit 2026-08-12. The power reconciler (`projector_power.py`,
pi-notes.md "Projector power") uses only the power subset; this sheet is
the map for anything else we ever want.

## Physical + framing

- DE-9 on the projector: pin 2 = RX, 3 = TX, 5 = GND (1/4/6/9 NC,
  7/8 RTSZ/CTSZ unused — flow control none). Null-modem crossover to the
  Pi's FTDI FT232R USB-RS232 cable (`/dev/serial/by-id/usb-FTDI_FT232R_
  USB_UART_A700DQNX-if00-port0`). 115200 8N1.
- Checksum on every frame = sum of all bytes after the first, mod 256.
- Frame shapes (`<ck>` = checksum):
  - 1-byte write:  `06 14 00 04 00 34 <grp> <fn> <val> <ck>`
  - read/query:    `07 14 00 05 00 34 00 00 <b1> <b2> <ck>`
  - remote key:    `02 14 00 04 00 34 02 04 <key> <ck>`
  - write ACK:     `03 14 00 00 00 14`
  - short reply:   `05 14 00 03 00 00 00 <val> <ck>` (1-byte values)
  - long replies:  `05 14 00 <len> 00 …` — 2-byte picture values, temp,
    error block (see below)
  - disabled fn:   `00 14 00 00 00 14` (function greyed out, e.g. no
    source; guide note 3)

## Power (what the reconciler uses)

| Action      | Frame                                    |
|-------------|------------------------------------------|
| Power ON    | `06 14 00 04 00 34 11 00 00 5D`          |
| Power OFF   | `06 14 00 04 00 34 11 01 00 5E`          |
| Read status | `07 14 00 05 00 34 00 00 11 00 5E`       |

Status reply `05 14 00 03 00 00 00 <s> <ck>`: s = 0 standby (ck 17),
1 warming (18), 2 on (19), 3 cooling (1A). Alternate richer read
`07 14 00 05 00 34 00 00 11 26 84` answers the same codes. Guide note 5:
don't send other commands during warm-up/cool-down. Live gotchas: warm-up
takes >60 s to report `on`; aborting a warm-up mutes status replies ~1 min.

## Telemetry reads (live-probed 2026-08-12)

- **Operating temperature** — `07 14 00 05 00 34 00 00 15 03 65`.
  Reply `05 14 00 0A 00 00 00 <t0 t1 t2 t3> … <ck>`: little-endian dword
  at data offset 7, tenths of °C. Our unit answered
  `… 18 01 00 00 …` = 0x118 = 28.0 °C shortly after lighting. (The
  guide's example response contains a typo — one extra 0x00 before the
  value bytes; trust the checksummed wire format above.)
- **Light-source hours (undocumented)** — `07 14 00 05 00 34 00 00 15 01
  63`. Reply `05 14 00 06 00 00 00 <h0 h1 h2 h3> <ck>`, dword at data
  offset 7. Our unit: 0xA2 = 162, matching a lightly-used unit —
  confirm once against OSD ▸ Information ▸ Light Source Usage Time.
  (`15 02` no answer; `15 00` answers zero.)
- **Error status block** — `07 14 00 05 00 34 00 00 0C 0D 66`.
  Reply `05 14 00 16 00 …`: 20 service items (items 0–17 one byte,
  item 18 = burn-in error minutes as 4 bytes, item 19 lamp status,
  item 20 lamp error 2 bytes; guide note 2). Our unit: all zeros —
  clean error history.
- **Standby behavior**: the whole sensor/settings bank answers zeros or
  the short form until the light engine runs — only power/status reads
  are meaningful in standby.

## Full control surface (guide table, 194 rows)

Reads exist for everything listed here unless noted; writes shown with
the identifying `<grp> <fn> <val>` bytes so any frame can be built with
the checksum rule.

- **Source select** (`13 01 <v>`): 0 D-Sub/Comp1, 8 D-Sub/Comp2,
  3 HDMI 1, 7 HDMI 2, 5 composite, 6 S-Video. Read `13 01`.
- **Light-source mode** (`11 10 <v>`): 0 Normal, 1 Eco, 4/5/6/7/8 =
  Custom 20/40/60/80/100 % — **direct laser dimming**. Read `11 10`.
- **Volume**: up `14 01 00`, down `14 02 00`, set `13 2A <v>`; read
  `14 03`. **Mute** (`14 00 <0|1>`, needs an active source, note 6).
- **Blank** (`12 09 <0|1>`) — instant picture kill, no cool-down.
  **Freeze** (`13 00 <0|1>`).
- **Picture**: aspect (`12 04`: auto/4:3/16:9/16:10/native + cycle),
  color mode (`12 0B`: brightest/movie/standard/photo/presentation),
  color temp (`12 08`), brightness/contrast/hue/saturation/gain/
  sharpness inc-dec + 2-byte value reads, keystone V (`12 0A`) /
  H (`11 31`), overscan, Brilliant Color 0–10, primary-color (RGBCMY)
  calibration, HDMI format RGB/YUV/auto + range (note 4: enhanced
  0–255, normal 16–235), 3D sync + invert.
- **Remote-key injection** (`02 14 00 04 00 34 02 04 <key> <ck>`):
  Menu 0F, Exit 13, Up 0B, Down 0C, Left 0D, Right 0E, Source 04,
  Enter 15, Auto 08, MyButton 11 — the full OSD is drivable over
  serial, so menu-only settings are scriptable.
- **Misc**: splash screen, high-altitude mode, projector position
  (front/rear × table/ceiling), CEC on/off, quick auto search, message
  on/off, 22 OSD languages, reset-all / reset-color, lamp-mode cycle,
  remote-control address code 1–8, AMX discovery string.

The guide's "value mapping tables 3.2.1/3.2.2" for 1- and 2-byte reads
live in ViewSonic's separate cross-model doc ("ViewSonic Projector RS232
v1.19", viewsonicvsa.freshdesk.com article 43000470420) — fetch that if a
picture-value read ever needs exact scaling.

## Ad-hoc probe snippet

Stdlib-only (the Pi has no pyserial), reconciler suspended via
`.projector-manual` while poking:

```python
import os, termios, select, time
P = "/dev/serial/by-id/usb-FTDI_FT232R_USB_UART_A700DQNX-if00-port0"
fd = os.open(P, os.O_RDWR | os.O_NOCTTY | os.O_NONBLOCK)
t = termios.tcgetattr(fd)
t[0]=t[1]=t[3]=0; t[2]=termios.CS8|termios.CREAD|termios.CLOCAL
t[4]=t[5]=termios.B115200; t[6][termios.VMIN]=t[6][termios.VTIME]=0
termios.tcsetattr(fd, termios.TCSANOW, t)
body=[0x14,0x00,0x05,0x00,0x34,0x00,0x00,0x15,0x03]   # temp read
os.write(fd, bytes([0x07]+body+[sum(body)&0xFF]))
buf=b""; end=time.monotonic()+1.0
while time.monotonic()<end:
    if select.select([fd],[],[],0.05)[0]:
        buf+=os.read(fd,64)
print(buf.hex(" "))
```
